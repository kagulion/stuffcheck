# AGENTS.md — руководство по настройке проекта для AI-агента

`AGENTS.md` — один из самых важных файлов в проекте, где используется AI-ассистент.  
Он **не для пользователей** и **не заменяет** `README`. Он написан для **AI-агента**, который помогает разрабатывать приложение.

Цель этого файла — дать агенту всю необходимую информацию о продукте, стеке, правилах, рабочем процессе и ограничениях проекта **до того**, как он начнёт писать код.  
Это позволяет избежать неоднозначности и гарантирует, что агент будет действовать в рамках утверждённой системы.

---

## 1. Роль и позиция агента

**Вы** — мыслитель продукта.  
**AI-агент** — исполнитель, который следует вашим инструкциям.

Агент **не принимает** архитектурных или продуктовых решений. Его задача — реализовывать то, что вы описали.

**Хороший стартовый запрос** (даёт агенту чёткие рамки):

> «Ты строишь обучающую платформу, где авторы создают курсы в Sanity, а учащиеся просматривают, смотрят уроки и ищут по всему контенту. Поиск должен быть основан на данных Sanity, возвращать структурированные карточки и ссылаться на таймкоды в видео. Перед реализацией напиши промпт, утверди его, а затем строго следуй плану».

**Плохой запрос** (слишком свободный):

> «Сделай обучающую платформу с AI-поиском».

---

## 2. Что мы строим (описание продукта)

Это **обучающая платформа**:

- **Авторы** создают курсы в **Sanity**.
- **Учащиеся** используют **Next.js‑приложение** для просмотра курсов, открытия уроков, просмотра видео и поиска.
- **Ключевая фича** — интеллектуальный поиск, который выдаёт **ранжированные карточки** с результатами и умеет ссылаться на точные моменты в видео.

**В область входят**:  
модель контента Sanity, аутентификация, каталог, страница курса, страница урока, страницы преподавателей, прогресс учащихся, аналитика (PostHog), импорт транскриптов, настройка поиска и сам поиск.

**За рамками**:  
не добавлять фичи, которые не перечислены выше. Не перестраивать существующее.

---

## 3. Рабочий процесс AI-агента

Агент **не начинает писать код сразу**. Он следует этому процессу:

1.  Прочитать `AGENTS.md`.
2.  Прочитать указанные навыки и вспомогательные документы.
3.  Изучить существующий код и конфигурацию.
4.  Задать **один** уточняющий вопрос, если задача действительно неоднозначна.
5.  Создать **промпт для реализации** в папке `prompts/`.
6.  Запросить ваше **утверждение**.
7.  Начать писать код **только после утверждения**.
8.  Выполнить все проверки.
9.  Завершить **кратким отчётом** (см. ниже).

**Отчёт после завершения** должен содержать три раздела:

- **Что я сделал**
- **Тестирование** (что и как проверял)
- **Требует вашего внимания** (проблемы, допущения, вопросы)

## 4. Правила работы с пользовательским интерфейсом

**Агент не является дизайнером**. Вы предоставляете:

- скриншоты десктопной версии (или Figma MCP),
- и текстовое описание.

Агент обязан **в точности воспроизвести** эталон (включая расположение, отступы, типографику, цвета, состояния).  
Для мобильных устройств эталона нет → адаптация делается **разумно**, но десктопный вид остаётся приоритетным.

**Важно**:

- Использовать существующие компоненты и паттерны Tailwind, прежде чем добавлять новые стили.
- При наличии эталонного изображения — оно является **абсолютным источником истины**.

---

## 5. Навыки и документация, которые должен использовать агент

Не полагайся только на память — читай актуальные руководства:

- **Sanity best practices** — для схем, GROQ, Portable Text, TypeGen, интеграции.
- **Sanity migration** — для импорта контента.
- **Sanity Context setup** — для подключения поиска через Context MCP.
- **Context tuning** — определяет, какой контент доступен поисковому агенту.
- **Agent shaping** — задаёт поведение поискового агента (что возвращать, чего избегать).
- **Локальные документы Next.js** (в `node_modules`) — всегда читать перед работой с Next.js.

---

## 6. Разделение ответственности (границы)

- **Браузер** — только отображает UI и вызывает безопасные серверные маршруты.
- **Сервер** — выполняет всю работу с приватными данными, вызывает LLM, работает с Sanity Context MCP.
- **Sanity Studio** — только для контент-менеджмента.
- **Clerk** — аутентификация.
- **PostHog** — аналитика.
- **Обработка видео** — происходит в автономных скриптах, **не во время запроса** пользователя.

**Запрещено**:

- Хранить приватные токены в клиенте.
- Вызывать LLM или MCP напрямую из браузера.
- Писать прогресс или контент напрямую из браузера.

## 7. Технологический стек

- Next.js (App Router)
- TypeScript
- Tailwind CSS
- Sanity Studio
- `next-sanity`, `@sanity/image-url`, `@portabletext/react`
- Clerk
- PostHog
- Sanity Context MCP
- Vercel AI SDK
- OpenAI API
- Zod
- `react-markdown` (только для рендеринга ответов поиска)

**Что не использовать**:

- Публичные наборы данных для приватного контента.
- Хранение токенов в клиентских компонентах.
- Отдельный бэкенд-фреймворк (всё в Next.js).
- Аутентификацию Sanity (используем Clerk).
- Семантический поиск, если нет эмбеддингов (только резерв по ключевым словам).

---

## 8. Принятые решения (не пересматривать)

- Поиск — это **полноэкранная страница результатов**, а не чат-бот.
- Результаты поиска — **структурированные карточки** (не сырые JSON).
- Поиск **всегда основан на реальных данных** Sanity.
- Видеоинтеллект хранится в отдельных документах `Video`.
- Для таймкодов сначала проверяются **главы**, затем — фрагменты транскрипта.
- Воспроизведение видео **остаётся на сайте** через встроенные плееры (YouTube, Vimeo, Bunny).
- Модули **встроены внутрь курсов**, а не являются отдельными документами.
- Уроки — отдельные документы; их порядок определяется порядком в курсе.
- Прогресс привязан к `userId` из Clerk.
- PostHog отправляет только значимые события обучения (не токены и не личные данные).

## 9. Модель данных

### Курс (Course)

- заголовок, слаг, краткое описание, обложка, уровень, цена, опциональный флаг «популярный», количество студентов, результаты обучения, ссылка на преподавателя, ссылка на категорию, **упорядоченные модули**.

### Модуль (Module)

- встроен в курс, не существует отдельно.
- заголовок, краткое описание, **упорядоченные ссылки на уроки**.

### Урок (Lesson)

- отдельный документ.
- заголовок, слаг, URL видео, миниатюра, длительность, флаг бесплатного просмотра, количество студентов, заметки (Portable Text), ключевые моменты, необязательный «про-совет», ресурсы.
- **не хранит** ссылку на родительский курс (она определяется через курс).

### Преподаватель (Instructor)

- имя, слаг, фото, специализация, биография.

### Категория (Category)

- заголовок, слаг, описание.

### Видеодокумент (Video)

- создаётся при обработке видео.
- содержит `videoId`, URL видео, массив **глав** (startSeconds, label) и массив **фрагментов транскрипта** (startSeconds, text).
- **не возвращать** весь транскрипт целиком — только фрагменты по запросу.

### Документ контекста агента (Agent Context)

- содержит фильтр по контенту и инструкции для поискового агента.
- позволяет настраивать поиск без изменения кода.

### Прогресс (Progress)

- ключ — `clerkUserId`.
- хранит список завершённых уроков и последнюю позицию в уроке.
- запись прогресса только через **серверный маршрут**, не из браузера.

## 10. Обработка видео (индексирование)

**Видео не ищется по URL** — нужен транскрипт и главы.

Процесс **автономный** (выполняется заранее):

1.  Скрипт загружает транскрипт и данные глав.
2.  Разбивает их на осмысленные фрагменты с таймкодами.
3.  Сохраняет в Sanity как документы `Video`.

Поиск использует эти подготовленные документы — **никакой тяжёлой работы во время запроса пользователя**.

**Поддержка провайдера** означает, что работают и **индексация**, и **воспроизведение**.  
Нельзя утверждать поддержку, если нельзя перематывать к моменту или получать фрагменты.

---

## 11. Конфигурация поиска (Context-документ)

В отдельном документе `Agent Context` задаются:

- **Что искать** (курсы, уроки, заметки, ключевые моменты, главы, фрагменты транскрипта).
- **Чего избегать** (внутренние токены, конфиденциальные данные, полные транскрипты).

Критические правила продублировать и в системном промпте — для надёжности.

---

## 12. Поведение поиска

- Поиск отдаёт **страницу с карточками результатов**.
- Типы результатов:
  - **Видеомомент** — ссылается на конкретную секунду в уроке (показывает курс, модуль, урок, таймкод).
  - **Урок** — ссылается на урок (курс, модуль, урок, ключевые моменты).
- Видеодокумент (`Video`) **не показывается** как результат — учащийся видит **урок**.
- Ранжирование: прямые совпадения в названии урока выше, чем косвенные упоминания.
- **Обоснованность (grounding)**: никогда не выдумывать курсы, уроки, цены, таймкоды и т.д. — только реальные данные.

---

## 13. Типичные ошибки и предостережения

- Sanity Context может требовать развёрнутого Studio для работы.
- Если семантический поиск отключён — нужен резерв по ключевым словам.
- Промпты с шаблонными литералами ломаются из-за обратных кавычек — экранировать.
- Изменения промпта поиска требуют перезапуска сервера.
- Не возвращать весь массив транскриптов — контекст переполнится.
- Токены чтения Sanity — строго на сервере.

**Безопасно для клиента**: публичные ключи Clerk, публичные ключи PostHog.  
**Небезопасно**: секреты Clerk, токены Sanity, ключи OpenAI, приватные ключи PostHog.

---

## 14. Проверки, которые агент обязан выполнить

Перед завершением задачи агент **обязан**:

- `lint` (проверка линтером)
- `type-check` (проверка типов TypeScript)
- `build` (сборка, если менялись маршруты или серверный код)
- Запустить dev-сервер и открыть страницу в браузере
- Протестировать счастливый путь, пустые состояния, некорректные вводы
- Для изменений в Sanity — открыть Studio и проверить схемы, создание контента, импорт
- Для поиска — проверить реальные запросы, несвязанные запросы, отсутствие выдумок, переход по таймкодам.

**Агент не может утверждать, что проверка пройдена, не выполнив её.**

---

## 15. Правила «в случае сомнений»

Если задача неясна, агент следует этим принципам:

- Делай минимально необходимое.
- Используй соответствующий навык/документацию.
- Соблюдай границы между клиентом и сервером.
- Никогда не раскрывай приватные токены.
- Точно воспроизводи предоставленный UI.
- Проверяй существующую конфигурацию перед хардкодом.
- Создай промпт и получи утверждение.
- Выполни все проверки.
- Приложи точные шаги для ручного тестирования.
